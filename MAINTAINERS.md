Maintainers review and merge pull requests, triage issues, cut releases, handle security reports privately and enforce the [Code of Conduct](CODE_OF_CONDUCT.md).

**Contact.** For anything public, open an [issue](https://github.com/SriSatyaLokesh/pariksha/issues) or a [discussion](https://github.com/SriSatyaLokesh/pariksha/discussions). For a security vulnerability, use the private route in [SECURITY.md](SECURITY.md) — never a public issue.

## Becoming a maintainer

There is no fixed quota of contributions. What we look for is a pattern over a few months: pull requests that land without needing to be rewritten, reviews that catch real problems, and judgement that matches the [principles in CONTRIBUTING.md](CONTRIBUTING.md) — zero cost, privacy first, the server as the only source of truth, flag-never-judge, accessible by default.

If that sounds like you, say so in a discussion or ask an existing maintainer. New maintainers are added by agreement of the current ones, and a maintainer who goes quiet for six months moves to the list of past maintainers — no hard feelings, and the door stays open.
