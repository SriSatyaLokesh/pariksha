# apps/web

Candidate and admin interfaces for Pariksha. React + Vite + TypeScript, with separate bundles so candidates download as little as possible.

**Status:** the landing page, design tokens, and the two Vite entry points (candidate `exam.html`, admin `admin.html`) are built. The test builder, the candidate runtime, proctoring and results screens are built, and the app is deployed on Cloudflare Workers static assets — see [deploy/cloudflare/README.md](../../deploy/cloudflare/README.md). Per-phase status is in [the roadmap](../../docs/ROADMAP.md). Requirements: [PRD — Candidate experience](../../docs/PRD.md#candidate-experience) and [Creating and configuring tests](../../docs/PRD.md#creating-and-configuring-tests).

**End-to-end tests.** `pnpm --filter @pariksha/web e2e` walks a fresh instance from the landing page to a signed-in, empty dashboard in Chromium. It starts three localhost processes itself — the built site behind `vite preview`, the Node API, and an OpenID provider that exists only in `e2e/stub-idp.mjs` — so it needs no credentials, no container and no network, and its database is `:memory:`, which is what makes every run a first run. Chromium only: this is a smoke test of one flow, not cross-browser coverage. It is deliberately outside `pnpm test`, which stays the fast unit suite.

**`SITE_URL`** is the one build-time origin every absolute URL on the landing page is derived from — canonical, Open Graph, the JSON-LD `@id`s, `sitemap.xml`, `robots.txt`'s `Sitemap:` line and `llms.txt` (design contract SEO-6). It is read from the `SITE_URL` environment variable; `scripts/prerender.mjs` throws rather than build if it is unset or is not an absolute `https` origin, because a canonical pointing at a non-serving host is worse than no canonical at all. There is no default: every caller passes it in. Run a local build as `SITE_URL="https://<name>.workers.dev" pnpm build` (`turbo.json` declares `SITE_URL` on the `build` task, so the value reaches the prerender and is part of the cache key). The test suite passes it straight to `runPrerender`, using `https://pariksha.example` since the assertions compare against the variable, never a literal. The deploy workflow reads a repository variable named `SITE_URL`, alongside the existing `DEPLOY_WEB`, and has no fallback because that build is the one that gets served; CI falls back to the tests' non-serving origin until the variable is set, since its `dist/` is thrown away. The real value (the `workers.dev` origin, or a custom domain once one exists) is the owner's to set — see OQ-1 in the design contract — and is not hard-coded anywhere in this repository.
