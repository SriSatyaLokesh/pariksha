## The nine declared deviations

1. **`status = "published"` — justified.** `TestStatus = "draft" \| "published" \| "closed" \| "archived"` (`packages/db/src/repo/tests.ts:7`) is the plan's `Interfaces` block verbatim and matches the planner's ruling; `publishTestVersion` is the only writer; a repo-wide grep finds no reader of `"open"` other than the wire-side `TestState` union and one fixture literal, so nothing breaks. Directly covered at `packages/db/test/repo/tests.test.ts:113`. It does expose finding 5 — the wire type has no `"published"` member and `toWire`'s `unknown` return hides it.
2. **Five fixtures to `version: 2` — justified, nothing weakened.** Checked individually: `apps/api/test/banks.test.ts:177`, `packages/db/test/repo/banks.test.ts:94/142/175` and `identifiers.test.ts:35` each still publish a version that names the question and still assert the same outcome; three of them now do it with a draft v1 *also* present, which is strictly stronger than what they tested before. `responses.test.ts` and `scoping.test.ts` changed only for `createTest`'s new return shape. The one thing it bakes in is incoherent data (`current_version = 2` beside `draftVersionsByTest` reporting 1) — Task 11's to resolve, not a regression here.
3. **`draftVersionsByTest` — justified.** No collision: Task 3's plan text declares `getDraftVersion`/`putDraftVersion`. The query is what it claims — one statement, `published_at IS NULL`, optionally narrowed by `test_id`, no per-row round trip. Registered in `REPO_FUNCTIONS` through `repo/index.ts` and enforced by `packages/db/test/repo/scoping.test.ts:76`.
4. **`TestList` wiring and the out-of-scope `dashboard.tsx` edit — not justified as delivered.** The wiring is real and correct (`organiser.tsx:157-166`), and the Dashboard test change is a legitimate consequence of the empty state genuinely going away. But the test the whole justification rests on was never written. Critical 1.
5. **`run_worker_first = ["/api/*", "/t/*"]` — justified; one phase-level note.** It is load-bearing: without it `ASSETS.fetch` answers every `/t/<code>` with `404.html` before Hono runs, which is proven in Miniflare (`apps/api/test/worker.test.ts:131-137`) rather than argued, and the pin in `apps/web/test/hosting.test.ts:116` is an exact-match regex so a third entry fails the suite. As a public unguarded route it holds up: the redirect is relative and leaks neither `wsp_` nor `tst_` (`apps/api/test/tests.test.ts:178`), the 404 body is the generic envelope, and an unknown code and a code in another workspace are indistinguishable in status and in work done — one query either way, because the code is globally unique by design. The note is that `/t/*` is now a billed, unauthenticated, unrate-limited D1 read, and this repo has no rate limiting anywhere; that is a phase-level gap to raise, not Task 2's to invent.
6. **"Address" relabel — not justified.** Finding 6. Renaming shipped copy to disambiguate a test selector is the wrong direction; `within(form)` costs one import.
7. **`fireEvent` + explicit `.focus()` — justified.** `@testing-library/user-event` is genuinely absent from `apps/web/package.json` (only `jest-dom` and `react`), and adding a dependency for one click is the wrong trade. The test does prove what it claims narrowly — the click handler moves focus nowhere. It cannot see the real defect, which is finding 8: the live region is inserted rather than updated, and `findByRole` only needs the node to exist.
8. **`qrcode-generator` 1.5.2 — justified.** `^1.5.2` matches the repo's caret convention for every other dependency; same MIT library, same size class. The admin-only guarantee is asserted exactly the way the katex-lazy tests are — `staticModules(twoEntryChunks, "island" \| "admin")` against a real Vite build (`apps/web/test/bundle.test.ts:244-251`), confirmed passing here.
9. **Late `tests.test.ts` / `parity.test.ts` (`3ccabd8`) — justified; the coverage is a superset of the plan's steps.** Every case the plan's Step 1 names is present: the T-01 shape, both `AC-02` cases, the cross-workspace slug, the slug lock in both directions, `S-09`, both `resolveShortCode` arms, all three Review Focus 1 cases, the Phase 5 column parity and the bare-unique enforcement — plus two the plan did not ask for (`publishTestVersion`'s status, and the row-and-draft-together invariant). Nothing was thinned.
