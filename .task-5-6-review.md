## B. SSRF audit of `apps/api/src/net/reachable.ts`

I ran the `refusal()` predicate directly against an evasion list rather than
reading it. **Genuinely closed**, each verified: decimal (`2130706433`), octal
(`0177.0.0.1`, `010.0.0.1`), hex (`0x7f.0.0.1`), short-form (`127.1`, `0`),
percent-encoded hosts (`%31%32%37%2e…`), IPv4-mapped IPv6
(`[::ffff:127.0.0.1]`, `[0:0:0:0:0:ffff:a00:7]`), `0.0.0.0`, `http://[::]`,
userinfo, non-web ports, every non-http scheme, and an unparseable URL. The
WHATWG-normalisation argument in the docblock is correct and the one `IPV4`
regex does catch every spelling. `%2e%2e` path tricks are irrelevant — the path
never affects host selection and no redirect is followed.

**One input defeats it: the trailing dot.** See **C1**.

IDN/punycode hosts (`http://ехample.com` → `xn--ample-ywe6i.com`) pass. That is
correct, not a finding: they are public names, the result is advisory, nothing
is stored, and no redirect is followed.

**The DNS limit is an acceptable documented limit, not a Critical.** Workers has
no resolver; the `ponytail:` comment names the ceiling and the Phase 11 upgrade
path (`dns.lookup` at the Node entry, refusals staying as the first gate); and
the plan's own Task 6 Step 3 sanctioned exactly this wording. Nothing is gained
by blocking the task on a limit the plan already priced.

**Guarding and budget — all confirmed.** `ROUTE_ACTIONS["POST …/check-url"]` is
`"tests.edit"` and pinned by a test; `getTest` runs before the fetch, so the
route is not a test-id-guessing fetcher; `expect(http).not.toHaveBeenCalled()`
backs the cross-workspace 404, the Viewer 403 and the no-url 400.
`SubrequestCounts.http` really counts — the budget test asserts
`{ db: 3, storage: 0, http: 1, total: 4 }`, and a refused URL
`{ …, http: 0, total: 3 }`; both read 3 before `countingDeps` wrapped `deps.http`.

## Findings

### Critical

**C1 — `apps/api/src/net/reachable.ts:93-100`: one trailing dot defeats every name-based refusal.**

`parsed.hostname` keeps the FQDN root label, so `localhost.` is not `localhost`,
`metadata.google.internal.` does not `endsWith(".internal")`, and `intranet.`
contains a dot so the single-label check passes. Verified by running the
predicate — these five all reach `fetch`:

```
**PASSES**  http://localhost./                    host=localhost.
**PASSES**  http://metadata.google.internal./     host=metadata.google.internal.
**PASSES**  http://foo.local./                    host=foo.local.
**PASSES**  http://intranet./                     host=intranet.
**PASSES**  http://metadata./                     host=metadata.
```

(`http://localhost．/` with the Unicode full-width stop normalises to the same
thing and also passes. `http://127.0.0.1./` is **not** affected — the IPv4
parser drops the empty trailing part — which is exactly why the gap is easy to
miss: the literal half of the table looks fine.)

Failure scenario: on the Docker deployment this module's own header names as its
threat model, any Author pastes `http://metadata.google.internal./` into "Try a
link" and the server fetches the cloud credential endpoint; `http://localhost./`
reaches the API's own loopback. Every resolver in the path strips the root label.

Fix (verified to close all five while `example.com` and `sub.example.co.uk` still
pass):

```ts
const host = parsed.hostname.toLowerCase().replace(/\.+$/, "");
```

Add the five URLs above to the `it.each` refusal table in
`apps/api/test/reachable.test.ts:38`.

### Major

**M1 — `apps/web/src/components/testbuilder/RegistrationForm.tsx:292-325`: the radio/checkbox group branch applies none of `shared`.**

`shared` (`:269`) carries `aria-required`, `aria-invalid` and `aria-describedby`
and is spread onto the text, dropdown and consent controls — but the
`CHOICE_TYPES && !== "dropdown"` branch returns its own `<fieldset>` and never
uses it. A required radio group is not programmatically required, an errored one
is not programmatically invalid, and `errorText`'s `<p id={errorId}>` and
`help`'s `<p id={helpId}>` are referenced by nothing.

Nothing catches it: `form-builder.test.tsx:163` only exercises `short_text`, and
the axe run at `:283` uses `FORM_TEMPLATES.campus_hiring`, whose only choice
field is a `dropdown` — so no test in the suite ever renders this branch, and
axe would not flag a missing `aria-required` anyway.

Scenario: a candidate on a screen reader submits with the required "Stream"
radio group blank. "This answer is required." renders visually inside the
fieldset, is announced by nothing, and is reachable only by reading the whole
form again. `O-04` / WCAG 2.1 AA.

Fix: put `aria-required`, `aria-invalid` and `aria-describedby` on the
`<fieldset>` (`role="radiogroup"` is already implied by the fieldset+legend for
the radio case), and add a radio or checkbox field to the axe fixture.

**M2 — `apps/web/src/components/testbuilder/FormBuilder.tsx:159` and `:377-383`: the Column name box can rename one field onto another's id, and every later edit then hits both.**

`updateField` keys on `field.id` (`spec.fields.map(f => f.id === id ? … : f)`),
and the Column name handler accepts any sanitised, non-empty string with no
collision check. `ReorderableList`'s `keyOf={f => f.id}` and `RegistrationForm`'s
`key={field.id}` / `values[field.id]` all assume uniqueness.

Scenario: add an Email field (id `email`), add a Short text field, rename its
column to `email`. Both fields now have id `email`; typing a label into either
rewrites both, React emits duplicate keys, and the preview shares one value.
`validateTest` reports the duplicate only at publish, by which point the author
has silently lost a field's configuration.

Fix: reject a rename to an id another field already holds — one
`spec.fields.some(f => f !== field && f.id === id)` guard at the rename site.

**M3 — `packages/core/src/validate.ts` and `apps/web/src/components/testbuilder/FormBuilder.tsx:436`: nothing refuses an unsafe or unparseable `validation.pattern`.**

`assertSafeRegex` was newly exported from `@pariksha/core` with the stated reason
"so the preview refuses exactly the patterns the server refuses"
(`packages/core/src/index.ts:61-66`). Its only caller in `apps/web` is
`RegistrationForm.validateField:154`, inside a `try`/`catch` that **swallows the
throw**. `FormBuilder` imports it nowhere. `validateTest` does not check it
either, so there is no server refusal to mirror.

`apps/web/test/testbuilder/form-builder.test.tsx:316-327` asserts the swallow and
its comment says "the builder shows it to the organiser instead" — the builder
does not. This is #57's own acceptance row: *"Validation that cannot be satisfied
(min above max, **a regex matching nothing allowed**) is caught in the builder
with cause and fix."* Only the first half shipped.

Scenario: an organiser sets the `roll_number` pattern to `([a-z]+)+$`. The
builder is silent, the preview silently accepts every answer, the draft saves,
the test publishes. PRD `C-03` says registration values are checked on the
server — Phase 6 compiles that pattern per registration and the Worker burns its
CPU budget on every candidate. The lesser variant is just as bad: an unparseable
pattern makes the field's format rule silently inert and bad data lands in the
results CSV.

Fix: wrap `assertSafeRegex(v.pattern)` in the Pattern editor and render the
message in the same `role="alert"` row `unsatisfiable` uses; and add one
`issues.push` in `validateTest` so the publish gate refuses it too.

**M4 — `apps/api/src/routes/tests.ts:100-116`: the strip is by keyword, not by value, so it also drops `access_code`'s `minLength: 4` — a value bound, not an emptiness floor.**

Proved against the pre-generalisation gate:

```
REJECT -> accept   <<< WIDENED   access_code 1 char (schemas/test-1.json:96, minLength 4)
REJECT -> accept   <<< WIDENED   access_code empty
```

The docblock at `:140-155` states *"Nothing that bounds a value is touched …
every `type`, `enum`, `pattern`, `minimum`, `required` below the root and
`additionalProperties: false` runs exactly as import will one day run it."*
That is now false for this one key, and there is no publish-time replacement:
`validateTest` checks `access_code !== undefined`, never its length.

Scenario: an organiser sets a one-character `link_code` access code. It saves, it
passes `validateTest`, it publishes — and the test's own export is then rejected
by the product's own import, breaking `docs/test-format.md`'s stated portability
guarantee ("a test built on one Pariksha installation runs unchanged on another").

Fix (laziest, and consistent with how the options floor was re-homed): one
`issues.push` in `validateTest` — "an access code must be at least 4 characters" —
and correct the docblock's claim. Narrowing the strip to floors whose value is
`1` is the alternative, but it would re-break the mid-build dropdown this task
deliberately unblocked.

**M5 — `apps/web/src/components/testbuilder/FormBuilder.tsx:473` and `RegistrationForm.tsx:34-45`: `validation.default_country` is write-only; the phone field has no country code at all.**

The builder collects "Default country" as free text, uppercased, with no
ISO-3166 check (the schema has no pattern for it either, so `"INDIA"` is legal
everywhere). `FIELD_INPUT.phone` ignores it, `validateField` never reads it, and
the preview renders a bare `<input type="tel">`.

`T-16` says "phone (**with country code**)"; #57 lists "country code" among the
validation this task ships; the plan's Step 3 names the control ("a country-code
picker is a `<select>` of dialling codes, not a dependency").

The deferral-to-Phase-6 argument does not hold, and this is the judgement asked
for on declared defect 6: `RegistrationForm.tsx` is **the file Phase 6 mounts
unchanged** — that is its entire stated reason for existing in Task 5 rather than
Task 6. Deferring the control guarantees Phase 6 edits it. Either render the
country affordance now, or — at minimum, if the `<select>` is genuinely to wait —
stop collecting a value nothing consumes: hide the control, or mark
`default_country` with a `ponytail:` comment naming Phase 6 and add the row to
the plan's "Known deferrals". Collecting it and silently dropping it makes the
preview lie about what a candidate sees, which is the one thing the shared
renderer exists to prevent.

### Minor (promoted — security / accessibility / file a fix already opens)

**m1 — `apps/api/src/net/reachable.ts:130-141`: `timeout` is a coarse but real timing oracle, and the docblock does not say so.**
Every refusal and every transport failure returns promptly; only a host that
accepts the connection and then stalls costs the full 5 s. For any public host on
80/443 that passed the refusals, that distinguishes "filtered / dropping packets"
from "refusing or not resolving". Small — authenticated Author, public names, web
ports, no body — but it is the one channel that survives the deliberate
"one indistinguishable `unverified`" design the `ReachResult.status` docblock
claims. Collapsing `timeout` into `unverified` would break the retry UX #58
requires, so the fix is one sentence in the docblock naming it, not code.

**m2 — `apps/web/src/components/testbuilder/RegistrationForm.tsx:103-113` (`domainAllowed`): adjacent `*` compile to adjacent unbounded quantifiers.**
Each `*` becomes `[^.]+`, so an organiser pattern of `*****.com` compiles to five
abutting `[^.]+` — the classic catastrophic-backtracking shape — and it runs in
the **candidate's** browser at registration. `assertSafeRegex` is not applied on
this path. One-character fix: `.replace(/\*+/g, "[^.]+")`.

**m3 — `apps/web/src/components/testbuilder/RegistrationForm.tsx:34`: every `short_text` field gets `autocomplete="name"`.**
`FORM_TEMPLATES.campus_hiring` alone has `college` and `roll_number` as
`short_text`, and `open_contest` has `country` — a browser offers the candidate's
name for all three. This is plan-faithful (#57's table says `short_text` → `name`)
so it needs the plan amended, not just the code; the `date` → `bday` label
heuristic one line below (`:48-55`) is the precedent for how to fix it.

**m4 — `packages/core/src/validate.ts:623`: stale "Save-time in class" comment.**
`ecd526f` withdrew that label; the rule is publish-time. One line, and it sits in
a file M3 and M4 already open.

### Minor (noted, not promoted)

- `FormBuilder.tsx:379` — `if (id !== "")` silently drops a keystroke whose
  sanitised value is empty, so a column name cannot be cleared and retyped.
- `RegistrationForm.tsx:301` — choice options use `key={option}`; duplicate
  option strings give duplicate React keys.
- `$defs/formField.options.items`'s `minLength: 1` was stripped with no
  publish-time replacement, so `["", ""]` passes both gates (the new `validateTest`
  rule counts options, it does not check they are non-empty).
- No rate limit on `POST …/check-url`. A workspace member can drive repeated
  outbound `HEAD`s at public hosts. Phase-wide gap (there is no rate limiter
  anywhere in `apps/api/src`), not Task 6's to invent.
