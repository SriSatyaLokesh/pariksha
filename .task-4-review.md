## Does `set_points_tolerance` being UI-less leave a trap for Task 13?

**Yes — two of them, and both are cheap to disarm now.**

1. **The number Task 13's row prints can only ever be 0 for a UI-built
   test.** Task 13's `sets_unbalanced` message is specified as
   `set A is 8 points, set B is 6 — 2 apart, tolerance 0`. T-11's wording is
   "differ in total points by more than **a set amount**", which presumes the
   amount is settable. Today it is settable only by hand-crafting a PATCH or
   by importing a file. So an organiser whose sets legitimately differ by a
   point sees an advisory row on every publish, forever, with no control
   anywhere that would let them accept the drift — and the obvious reading of
   that row is that the product is broken rather than that the knob is
   missing.
2. **The sharper one: `buildChecklist` passing an explicit `0` silently
   overrides the document.** Because precedence is
   `options.setPointsTolerance ?? doc.scoring?.set_points_tolerance ?? 0`, a
   caller that passes what looks like the harmless default —
   `validateTest(doc, bank, { setPointsTolerance: 0 })` — throws away a
   tolerance the file set. There is no production caller of `validateTest`
   yet (only `packages/core` tests), so Task 12 (import) and Task 13
   (checklist) will both write the first one, and the mistake is invisible:
   the publish gate quietly ignores a field the schema advertises, the export
   carries, and `test-format.md:137` promises "travels with the file".

   The rule is: **pass no `setPointsTolerance` at all unless the gate has its
   own reason to be stricter.** That is worth one sentence in Task 13's own
   text, because `?? 0` reads as "0 is the default" right up until someone
   writes the default out explicitly.

Both are documentation, not code, and both belong on Task 13 in `c0e8a96`'s
shape:

> **Note, from Task 4.** `scoring.set_points_tolerance` exists in the schema,
> the type and `validateTest`, but has no control — only a raw `PATCH` or an
> import can set it. Decide here whether `SetsPanel` grows a number input or
> whether the row says the tolerance is file-only; and call `validateTest`
> **without** `setPointsTolerance` so the document's own number is honoured —
> passing an explicit `0` silently overrides a file that asked for more.
